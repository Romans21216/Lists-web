# Contributing — Lists-web

Contributions require maintainer approval and rights to the submitted material.
Repository visibility is not permission to copy proprietary source or datasets.
Do not submit student data, private school rules, credentials, vendor material
without its required license, or unrelated game code/assets.

Use focused branches and pull requests. Explain the problem, investigated cause,
scope, behavior changes, tests, license/provenance impact, and deployment needs.
For data corrections include only public domain-level evidence. For code fixes
use disposable synthetic fixtures and add a regression for the original cause.
Do not mark a feature production-ready solely because syntax or unit tests pass.

Review formatting, Markdown links, spelling, publication scope, and secret
exclusions for documentation. Source imports need dependency and license
inventories; data imports need schema, provenance, and license review.
Never restart or deploy live services as an incidental contribution step.

Submitting a contribution confirms that you may submit it. It does not
automatically transfer copyright or authorize relicensing. Maintainers must
resolve contribution terms before incorporating third-party-owned material.

Contact: bp@amanwithcode.org.
